# `IMU Linux` SocketCAN 统计验证程序 (can_stat)

[TOC]

## 概述

	本项目是基于志翔`IMU`的 Linux SocketCAN **测试验证程序**，在 `feature/LinuxCanDemo` 解析示例的架构基础上，增加了**帧间隔与频率统计**功能。

	架构与 LinuxCanDemo 完全一致（驱动/队列/协议三层），差异仅在：协议层增加统计入口、主线程周期打印统计表格、退出时输出汇总。适用于验证 IMU 数据流的**帧率是否达标、间隔是否均匀、有无断流**。

## 功能特性

- `SocketCAN`驱动：内核级接收过滤器，只接收`0x091`~`0x098`报文（只匹配标准数据帧）
- 协议支持：`0x091`~`0x098`共 8 个数据报文解析（小端 intel）
- 自动开启推送（按需）：启动后若 2 秒宽限期内收不到首帧、或运行中数据流中断超过 3 秒，才下发`0x103`指令开启推送，之后每 3 秒重试直到数据恢复——数据正常时**一次都不发**，覆盖设备未开启推送/设备重启/推送意外关闭三种场景
- **帧级统计**：每个 ID 的帧数 / 平均Hz / 瞬时Hz（1 秒窗口）
- **帧间隔统计**：当前ms（当前帧−上一帧）/ 平均 / 最小 / 最大
- **设备时间戳差值**：0x091 相邻两包载荷时间戳之差 Δt（最新/平均/最小/最大统计）
- **最新帧解析**：实时表格下方按协议解析各 ID 最新一帧的物理量
- 完整数据收集：8 帧收齐解析出一组完整 IMU 数据（`BspCanProtocolPrintImuData()` 接口保留，默认不打印——实时解析区已逐 ID 展示，整版输出重复）
- 多线程设计：CAN 接收线程 + 协议解析/统计线程 + 主线程周期打印
- 帧级队列：`can_frame` 环形队列（单生产者单消费者）衔接两个线程
- 优雅退出：Ctrl+C 或限时到打印最终汇总与队列丢帧计数

## CAN数据报文定义

标准帧，每帧 8 字节，小端模式，频率与设备推送频率一致（本设备当前 1000Hz）：

| 报文ID | 字段1 | 字段2 | 单位 |
| ------ | ------------ | ------------ | ---- |
| 0x091  | 时间戳 uint64 |  | us |
| 0x092  | Roll | Pitch | ° |
| 0x093  | Yaw | IMU温度 | ° / ℃ |
| 0x094  | 四元数q1 | 四元数q2 |  |
| 0x095  | 四元数q3 | 四元数q4 |  |
| 0x096  | 加速度X | 加速度Y | m/s² |
| 0x097  | 加速度Z | 角速度X | m/s² / °/s |
| 0x098  | 角速度Y | 角速度Z | °/s |

## 环境要求

# 配置波特率并启用(波特率需与IMU一致, 协议默认1000Kbps)
sudo ip link set can0 down

```bash
./can_stat can0              # 数据流统计(功能1, 直到Ctrl-C)

# 或经 run.sh: ./run.sh can0 test [1]
```

## CAN指令验证(功能2, bsp_can_test.c)

依据协议文档 3.3.3 章对每条 CAN 交互指令做实测验证（帧格式逐 ID 对照固件工程 `bsp_parse.c` 核实），架构与串口 HEX 验证器一致：安全组/风险组、查询校验键→函数分发表、缓存驱动自动还原、安静模式逐条输出+汇总表。

- **帧格式**：标准帧，`can_id`=指令ID(0x100~0x115)，DLC=8，`data[0]`=操作符(0x00查询/0x01写RAM/0x02写FLASH)，`data[1..7]`=参数；应答帧同 ID，写操作应答 8 字节全 0
- **数据流容错**：内核过滤器只收 0x100~0x115，0x091~0x098 推送帧不进用户态
- **用例覆盖**（32 条）：安全组 15 查询 + YAW 归零；风险组 7 条 RAM 写入（频率避让档/坐标系切异值/数据流开关取反/0x22 推送取反/PPS 开关取反/精简流取反/零偏校准开启）验证后自动还原原值；**异常组 8 条**（与风险组同开关，预期以固件实际行为为准）：无效操作符静默（0x100/0x105/0x115 非法类型/未知 ID 0x116 均无应答）、无效操作符无效应答（0x101 回全 0）、非法频率档回落验证（固件回落 50Hz 档 5）、非法坐标系/PPS 模式直写行为确认+还原；复位重置表末
- **异常组发现**：固件 0x102 坐标系/0x109 PPS 模式**无值域校验直写**非法值（工具记录行为并立即还原；固件将来加校验时这两条会 FAIL 以提示行为变化）
- **压力/暴力模式**（功能2第3参数=2，对齐 HEX 验证器模式2）：① 无效请求静默（非法操作符 0xFF+未知 ID 0x116，预期无应答）；② 高频连发 200 帧不等应答（统计固件实际接收数）；③ 未知 ID 轰炸 200 轮（随机 0x116~0x1FF 后合法版本查询验证恢复，恢复率≥90% 判 PASS）；④ fuzz 随机请求轰炸 500 帧（固定种子可复现，只用版本/SN/未知 ID 无副作用集+随机操作符与参数）；每项结束版本查询探活（3 重试），失败自动 0x110 复位兜底重启再探活。CAN 适配：无字节流截断概念，以未知 ID 轰炸替代 HEX 截断恢复项。本机无 CAN 接口（无 sudo 建 vcan），已过逻辑单测 9 断言，真机验证待硬件接入
- **固件对照结论**（以固件为准的差异）：0x104 固件支持查询（文档标不支持，应答 `[1]`=子ID回显`[2]`=开关）；0x115 量程配置文档缺失但固件已实现（查询 `[1]`=类型 1 加计/2 角速度，应答量程小端 2 字节）；SN 低/高 8 字节固件按倒序填充；0x110 复位仅 RAM 档应答
- **有意排除**：CAN/串口波特率写入（FLASH+重启生效，改 CAN 波特率直接断链）、UART 开关写入（FLASH+重启生效）、0x115 量程写入（仅 FLASH 档掉电保存）、各 ID 的 FLASH 档（0x02）
- **风险组还原**：依赖安全组查询缓存构造还原帧（频率/坐标系/数据流/0x22/PPS/精简流回原值，零偏=清除校准值），还原动作不计分；缓存无效时用例自动 SKIP 保护

## 实时统计表格字段说明

终端下每 1 秒原地刷新（管道/重定向时每 5 秒打印）：

| 字段 | 单位 | 说明 |
|---|---|---|
| `ID` | — | CAN 标准帧标识符，范围 0x091~0x098（内核级过滤器，只收这 8 个 ID） |
| `帧数` | 帧 | 统计开始以来收到的该 ID 数据帧总数 |
| `平均Hz` | Hz | 平均频率 = (帧数−1) ÷ (首帧→末帧时间跨度)，全程平均 |
| `瞬时Hz` | Hz | 最近 1 秒滑动窗口内的帧率，反映当前实际节奏（与平均Hz对比可发现断流/变速） |
| `当前ms` | ms | **当前帧时间戳 − 上一帧时间戳**（该 ID 最近一次相邻两包差值），每收到一帧即更新 |
| `平均间隔ms` | ms | 所有相邻帧间隔的算术平均值 |
| `最小ms` | ms | 帧间隔最小值（抖动下界） |
| `最大ms` | ms | 帧间隔最大值（抖动上界，可发现掉帧/卡顿） |

## 数据解析区字段说明

统计表格下方为**数据解析区**，按协议文档 `01.Doc/用户协议.md` 3.3.2 节解析每个 ID **最新收到的一帧**：

| 列 | 说明 |
|---|---|
| `ID` | CAN 标准帧标识符 |
| `原始数据(B0~B7)` | 最新一帧的 8 字节原始数据（B0 = 报文第 1 字节） |
| `解析值` | 按协议解释后的物理量；多字节数值均为**小端模式(intel)** |

各 ID 字节布局：

| ID | B0~B3 | B4~B7 | 单位 |
|---|---|---|---|
| `0x091` | Timestamp 低 4 字节 | Timestamp 高 4 字节 | us（8字节 uint64） |
| `0x092` | Roll | Pitch | ° |
| `0x093` | Yaw | Temp | ° / ℃ |
| `0x094` | q1 | q2 | — |
| `0x095` | q3 | q4 | — |
| `0x096` | X_Acc | Y_Acc | m/s² |
| `0x097` | Z_Acc | X_Gyro | m/s² / °/s |
| `0x098` | Y_Gyro | Z_Gyro | °/s |

## 汇总输出

程序退出时打印 `=== 汇总 ===`：每个 ID 一行（总帧数/平均Hz/当前间隔/平均间隔/min/max）、0x091 时间戳差值 Δt 汇总（最新/平均/最小/最大/样本数），最后输出队列丢弃帧数（评估负载）。

## 0x091 设备时间戳差值（Δt）统计

`0x091` 报文载荷是设备内部时间戳（uint64，单位 us）。程序对**相邻两包 0x091 的时间戳做差**：

**Δt = 本包时间戳 − 上一包时间戳**（单位 ms，即"数据包2 − 数据包1"），与主机接收侧的`当前ms`相互独立：

- 两者接近 → 设备按真实节奏推流，时间戳可信；
- 接收间隔正常但 Δt 为 0 或跳变 → 设备时间戳本身异常（冻结/回绕/复位）。

### Δt 统计字段

| 字段 | 单位 | 说明 |
|---|---|---|
| `Δt统计: 最新` | ms | 当前包时间戳 − 上一包时间戳（每收到一帧 0x091 即更新） |
| `平均` | ms | 全部 Δt 样本的算术平均（理想值 = 推送周期，1000Hz → 1.000ms） |
| `最小` / `最大` | ms | Δt 极值；最大值明显偏离平均 → 设备侧存在跳变/丢拍 |
| `样本` | 个 | 已计算的相邻对数（= 帧数 − 1） |

## 判读参考

- 理想周期帧：`当前ms` 紧贴平均值小幅波动，`最小ms`/`最大ms` 对称包裹平均值。
- `最大ms` 明显大于平均值 → 存在掉帧或发送端卡顿。
- `瞬时Hz` 长期低于 `平均Hz` → 数据流变慢或已断流。
- 解析值为 0 且长期不变 → 发送端未更新该字段（结合原始数据字节判断）。

## 常见问题

### 1. 打开接口失败

```
ioctl SIOCGIFINDEX fail (接口不存在?)
```

- 确认接口名正确：`ip link show type can`
- 确认接口已UP：`ip link show can0` 中应有 `state UP`
- USB转CAN适配器需先加载驱动，如 `sudo modprobe gs_usb`
- 权限不足时使用 `sudo ./can_stat can0` 或将用户加入netdev组
