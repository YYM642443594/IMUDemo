# `IMU Linux` 串口统计验证程序 (uart_stat)

[TOC]

## 概述

	本项目是基于志翔`IMU`的 Linux 串口**测试验证程序**，参照 `feature/LinuxCanTestVerifDemo` 分支的统计方式与三层架构（驱动/队列/协议），通过串口接收志翔私有协议推送报文，实现**数据包1/2/3/4 的帧级统计与解析**。

	适用于验证 IMU 串口数据流的**帧率是否达标、间隔是否均匀、有无断流**，以及各包物理量解析正确性。

## 功能特性

- 串口驱动：`termios` 原始模式，默认 `921600 8N1`（协议默认），支持 9600~921600 常用波特率，使能 `ASYNC_LOW_LATENCY` 降低 USB 串口延迟
- 协议支持：志翔私有协议帧 `AA 55 | CMD | ID | LEN(2, 小端) | DATA | CRC16(2, 小端)`，LEN 为整帧长度
- **数据包统计与解析**（CMD=0x00 通用报文）：

| 数据包 | 报文ID  | 数据域长度 | 内容 |
|---|---|---|---|
| 数据包1 | `0x0001` | 87 字节 | 频率/日期时间/加计XYZ+模长/陀螺XYZ+模长/温度/姿态/四元数/磁场 |
| 数据包2 | `0x0010` | 44 字节 | 时间戳/加计XYZ/陀螺XYZ/姿态 |
| 数据包3 | `0x0013` | 105 字节 | 数据包1 全集+时间戳+PPS 锁定状态与模式+预留 |
| 数据包4 | `0x0022` | 38 字节 | 时间戳/加计XYZ/陀螺XYZ |

- **CRC16 校验**：初值 `0x3692`、多项式 `0x8408`（反向），计算范围=帧头至数据域末字节，**只统计校验通过的帧**
- **帧级统计**（与 CAN 分支字段对齐）：每个报文 ID 独立统计 帧数 / 平均Hz / 瞬时Hz（1 秒窗口）/ 帧间隔（当前ms / 平均 / 最小 / 最大）
- **最新帧解析**：实时表格下方按协议（小端 intel）解析各包最新一帧的物理量
- **设备时间戳差值Δt统计**（数据包2/3/4，同 CAN 分支 0x091）：相邻帧设备 us 时间戳之差的 最新/平均/最小/最大 统计，用于排查设备侧丢帧/乱序/时间戳重置；全样本无过滤，异常差值不丢弃、直接体现为极值
- 帧同步状态机：逐字节同步，坏 CRC 帧、非法长度帧自动剔除并可恢复同步，帧间夹垃圾字节不受影响
- 多线程设计：串口接收线程 + 协议解析/统计线程（字节流 SPSC 环形队列衔接）+ 主线程周期打印
- 优雅退出：Ctrl+C 或限时到打印最终汇总（接收字节数/CRC 通过帧数/队列丢弃字节/各包统计）

### 线程模型

```
UartRecvThread(生产者)  --字节流-->  UartQueue  --字节流-->  UartParseThread(消费者)
   阻塞read()        BspUartQueuePush()         BspUartQueuePop()   帧同步/CRC/统计/解析
                                                                     │
                                       主线程: 每秒 BspUartProtocolPrintStat() 刷新显示
```

## 构建与运行

```bash
# 一键编译运行（默认 /dev/ttyUSB0 @921600，直到Ctrl-C）
./run.sh

# 指定串口/波特率/限时10秒
./run.sh /dev/ttyUSB0 921600 10

# 手动编译
gcc -O2 -Wall -o uart_stat main.c drv_serial.c bsp_uart_queue.c bsp_uart_protocol.c -lpthread
```

用法：`./uart_stat [串口设备] [波特率] [持续秒数]`，持续秒数 0 或缺省=直到 Ctrl-C。

## 实时输出说明

终端下每秒原地刷新（管道输出则 5 秒全量打印）：

| 字段 | 单位 | 说明 |
|---|---|---|
| `帧数` | 帧 | 该报文累计收到的 CRC 通过帧数 |
| `平均Hz` | Hz | (帧数−1) ÷ (末帧时刻−首帧时刻)，全程平均 |
| `瞬时Hz` | Hz | 最近 1 秒窗口内帧数 ÷ 窗口时长 |
| `当前ms` | ms | 当前帧 − 上一帧的接收间隔 |
| `平均ms` | ms | 全部帧间隔的算术平均（理想值=推送周期） |
| `最小/最大ms` | ms | 帧间隔极值；明显偏离平均 → 存在断流或突发 |

解析区逐包显示最新物理量：加计（m/s²，静止时模长≈9.8）、陀螺（°/s）、温度（℃）、姿态（°）、四元数（模长应≈1）、磁场、设备时间戳（us）等。

Δt 统计每包一行 `0x10时间戳差值Δt: 最新 xx ms, 平均 xx ms, 最小 xx ms, 最大 xx ms, 样本 n`（数据包 2/3/4 各一行，无数据显示"等待第二个0xXX包..."，格式与统计语义均对齐 CAN 分支 0x091：全样本无过滤）：理想值=推送周期；全样本无过滤下极值即异常证据——最小 1ms 级毛刺/最大百万毫秒级跳变 → 设备侧时间戳回退或重置丢帧；平均接近推送周期仅极值毛刺 → 偶发抖动。

## 判读参考

- 50Hz 推送 → 平均间隔应 ≈ 20.0ms；1000Hz → ≈ 1.0ms
- `平均Hz` 与设置推送频率一致、`最大ms` 无大跳 → 流稳定无断流
- 队列丢弃字节 > 0 → 解析线程消费不及（正常情况应为 0）
- CRC 通过帧数 ≈ 接收字节数 ÷ 平均帧长 → 链路无误码

## 排障

- **统计/解析停滞、CRC 失败帧暴涨**：先查是否有别的进程占用同一串口（`lsof /dev/ttyUSB0`；曾因 30 分钟长跑的旧 uart_stat 实例未退出，新实例只收到残帧：11s 仅 2 帧通过、411 帧CRC失败）。两实例同时读会让字节流被瓜分，任何单实例都无法组出完整帧。
- **"最新帧解析"数值不动**：正常情况下每秒都在变（时间戳走秒/物理量微抖）；若完全冻结，优先怀疑串口被抢占而非协议解析（本工具解析为每帧无条件更新）。

## 已知限制

- 设备未授时时数据包 1/3 的日期时间为 1970 纪元起算（设备内部 uptime），属设备侧行为
- 数据包 4（0x0022）默认未开启推送（需 `AT+MSGID=22,1` 或 0x0011 指令开启），程序侧已支持解析
- 程序为纯被动接收，不主动下发推送开启指令（如需请参考 CAN 分支的按需下发思路扩展 0x0011 指令）
