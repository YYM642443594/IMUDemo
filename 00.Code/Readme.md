# `IMU Linux` SocketCAN 统计验证程序 (can_stat)

[TOC]

## 概述

	本项目是基于志翔`IMU`的 Linux SocketCAN **测试验证程序**，在 `feature/LinuxCanDemo` 解析示例的架构基础上，增加了**帧间隔与频率统计**功能。

	架构与 LinuxCanDemo 完全一致（驱动/队列/协议三层），差异仅在：协议层增加统计入口、主线程周期打印统计表格、退出时输出汇总。适用于验证 IMU 数据流的**帧率是否达标、间隔是否均匀、有无断流**。

## 功能特性

- `SocketCAN`驱动：内核级接收过滤器，只接收`0x091`~`0x098`报文（只匹配标准数据帧）
- 协议支持：`0x091`~`0x098`共 8 个数据报文解析（小端 intel）
- 自动开启推送：启动时自动下发`0x103`指令开启 IMU 的 CAN 数据推送
- **帧级统计**：每个 ID 的帧数 / 平均Hz / 瞬时Hz（1 秒窗口）
- **帧间隔统计**：当前ms（当前帧−上一帧）/ 平均 / 最小 / 最大
- **设备时间戳差值**：0x091 相邻两包载荷时间戳之差 Δt，统计 + 最近 64 包实时曲线（量程自适应）
- **最新帧解析**：实时表格下方按协议解析各 ID 最新一帧的物理量
- 完整数据收集：8 帧收齐打印一次完整 IMU 数据，容忍报文乱序
- 多线程设计：CAN 接收线程 + 协议解析/统计线程 + 主线程周期打印
- 帧级队列：`can_frame` 环形队列（单生产者单消费者）衔接两个线程
- 优雅退出：Ctrl+C 或限时到打印最终汇总与队列丢帧计数

## CAN数据报文定义

标准帧，每帧 8 字节，小端模式，频率与设备推送频率一致（本设备当前 1000Hz）：

| 报文ID | 字段1 | 字段2 | 单位 |
| ------ | ------------ | ------------ | ---- |
| 0x091  | 时间戳 uint64 |  | us |
| 0x092  | Roll | Pitch | ° |
| 0x093  | Yaw | IMU温度 | ° / ℃ |
| 0x094  | 四元数q1 | 四元数q2 |  |
| 0x095  | 四元数q3 | 四元数q4 |  |
| 0x096  | 加速度X | 加速度Y | m/s² |
| 0x097  | 加速度Z | 角速度X | m/s² / °/s |
| 0x098  | 角速度Y | 角速度Z | °/s |

## 环境要求

- Linux 操作系统
- GCC 编译器
- CAN接口（如 USB转CAN适配器），且已加载驱动
- IMU 的 CAN 推送链路无需提前配置：程序启动时会自动下发`0x103`指令开启推送

## 编译方法

### 方式一：一键脚本（推荐）

```bash
cd /path/to/IMUDemo/00.Code
./run.sh              # 编译并运行(默认can0, 直到Ctrl+C)
./run.sh can0 10      # 指定接口, 运行10秒自动汇总退出
./run.sh can1         # 指定其他CAN接口
```

脚本自动完成：gcc 编译 → 接口存在性检查 → 未 UP 时尝试 sudo 拉起 → 运行。

### 方式二：手动编译

```bash
gcc -O2 -Wall -o can_stat main.c drv_socketcan.c bsp_can_queue.c bsp_can_protocol.c -lpthread
./can_stat can0        # 一直跑到 Ctrl+C
./can_stat can0 10     # 限时 10 秒
```

## 运行方法

### 第一步：配置CAN接口

```bash
# 查看CAN接口是否存在
ip link show type can

# 配置波特率并启用(波特率需与IMU一致, 协议默认1000Kbps)
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
```

### 第二步：运行程序

```bash
./can_stat can0
```

## 实时统计表格字段说明

终端下每 1 秒原地刷新（管道/重定向时每 5 秒打印）：

| 字段 | 单位 | 说明 |
|---|---|---|
| `ID` | — | CAN 标准帧标识符，范围 0x091~0x098（内核级过滤器，只收这 8 个 ID） |
| `帧数` | 帧 | 统计开始以来收到的该 ID 数据帧总数 |
| `平均Hz` | Hz | 平均频率 = (帧数−1) ÷ (首帧→末帧时间跨度)，全程平均 |
| `瞬时Hz` | Hz | 最近 1 秒滑动窗口内的帧率，反映当前实际节奏（与平均Hz对比可发现断流/变速） |
| `当前ms` | ms | **当前帧时间戳 − 上一帧时间戳**（该 ID 最近一次相邻两包差值），每收到一帧即更新 |
| `平均间隔ms` | ms | 所有相邻帧间隔的算术平均值 |
| `最小ms` | ms | 帧间隔最小值（抖动下界） |
| `最大ms` | ms | 帧间隔最大值（抖动上界，可发现掉帧/卡顿） |

## 数据解析区字段说明

统计表格下方为**数据解析区**，按协议文档 `01.Doc/用户协议.md` 3.3.2 节解析每个 ID **最新收到的一帧**：

| 列 | 说明 |
|---|---|
| `ID` | CAN 标准帧标识符 |
| `原始数据(B0~B7)` | 最新一帧的 8 字节原始数据（B0 = 报文第 1 字节） |
| `解析值` | 按协议解释后的物理量；多字节数值均为**小端模式(intel)** |

各 ID 字节布局：

| ID | B0~B3 | B4~B7 | 单位 |
|---|---|---|---|
| `0x091` | Timestamp 低 4 字节 | Timestamp 高 4 字节 | us（8字节 uint64） |
| `0x092` | Roll | Pitch | ° |
| `0x093` | Yaw | Temp | ° / ℃ |
| `0x094` | q1 | q2 | — |
| `0x095` | q3 | q4 | — |
| `0x096` | X_Acc | Y_Acc | m/s² |
| `0x097` | Z_Acc | X_Gyro | m/s² / °/s |
| `0x098` | Y_Gyro | Z_Gyro | °/s |

## 汇总输出

程序退出时打印 `=== 汇总 ===`：每个 ID 一行（总帧数/平均Hz/当前间隔/平均间隔/min/max）、0x091 时间戳差值 Δt 汇总（最新/平均/最小/最大/样本数），最后输出队列丢弃帧数（评估负载）。

## 0x091 设备时间戳差值（Δt）统计与曲线

`0x091` 报文载荷是设备内部时间戳（uint64，单位 us）。程序对**相邻两包 0x091 的时间戳做差**：

**Δt = 本包时间戳 − 上一包时间戳**（单位 ms，即"数据包2 − 数据包1"），与主机接收侧的`当前ms`相互独立：

- 两者接近 → 设备按真实节奏推流，时间戳可信；
- 接收间隔正常但 Δt 为 0 或跳变 → 设备时间戳本身异常（冻结/回绕/复位）。

### Δt 曲线区

实时界面底部为 Δt 曲线：

| 项 | 说明 |
|---|---|
| 窗口 | 最近 64 个 Δt 样本（1000Hz 下约 64ms），横轴每字符 ≈ 1 包，左老右新 |
| 纵轴 | 星号 `*` 落点 = 样本值，量程按窗口内 min/max **自适应**，右侧标注 max / mid / min |
| 底线 | `_` 表示该列样本未落入当前行分桶（曲线基底） |

### Δt 统计字段

| 字段 | 单位 | 说明 |
|---|---|---|
| `Δt统计: 最新` | ms | 当前包时间戳 − 上一包时间戳（每收到一帧 0x091 即更新） |
| `平均` | ms | 全部 Δt 样本的算术平均（理想值 = 推送周期，1000Hz → 1.000ms） |
| `最小` / `最大` | ms | Δt 极值；最大值明显偏离平均 → 设备侧存在跳变/丢拍 |
| `样本` | 个 | 已计算的相邻对数（= 帧数 − 1） |

## 判读参考

- 理想周期帧：`当前ms` 紧贴平均值小幅波动，`最小ms`/`最大ms` 对称包裹平均值。
- `最大ms` 明显大于平均值 → 存在掉帧或发送端卡顿。
- `瞬时Hz` 长期低于 `平均Hz` → 数据流变慢或已断流。
- 解析值为 0 且长期不变 → 发送端未更新该字段（结合原始数据字节判断）。

## 常见问题

### 1. 打开接口失败

```
ioctl SIOCGIFINDEX fail (接口不存在?)
```

- 确认接口名正确：`ip link show type can`
- 确认接口已UP：`ip link show can0` 中应有 `state UP`
- USB转CAN适配器需先加载驱动，如 `sudo modprobe gs_usb`
- 权限不足时使用 `sudo ./can_stat can0` 或将用户加入netdev组
