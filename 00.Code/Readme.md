# `IMU Linux` 串口验证程序 (imu_test: 数据流统计 + AT指令 + HEX协议)

[TOC]

## 概述

	本项目是基于志翔`IMU`的 Linux 串口**测试验证程序**（单可执行 `imu_test`，参数选择功能），参照 `feature/LinuxCanTestVerifDemo` 分支的统计方式与三层架构（驱动/队列/协议），包含三种验证功能：

	- **功能1 数据流统计**：接收志翔私有协议推送报文，实现数据包1/2/3/4 的帧级统计与解析，验证帧率是否达标、间隔是否均匀、有无断流、物理量解析正确性。
	- **功能2 AT指令验证**：依据《用户协议》第2章逐条下发 AT 指令并按文档应答格式判定，验证完成后自动还原配置。
	- **功能3 HEX协议验证**：依据《用户协议》第3.2章串口交互协议，对全部报文 ID 逐一下发查询/写入帧并按应答格式判定（Len/CRC/值域），写 RAM 项验证后依据查询缓存自动还原。

## 功能特性

- 串口驱动：`termios` 原始模式，默认 `921600 8N1`（协议默认），支持 9600~921600 常用波特率，使能 `ASYNC_LOW_LATENCY` 降低 USB 串口延迟
- 协议支持：志翔私有协议帧 `AA 55 | CMD | ID | LEN(2, 小端) | DATA | CRC16(2, 小端)`，LEN 为整帧长度
- **数据包统计与解析**（CMD=0x00 通用报文）：

| 数据包 | 报文ID  | 数据域长度 | 内容 |
|---|---|---|---|
| 数据包1 | `0x0001` | 87 字节 | 频率/日期时间/加计XYZ+模长/陀螺XYZ+模长/温度/姿态/四元数/磁场 |
| 数据包2 | `0x0010` | 44 字节 | 时间戳/加计XYZ/陀螺XYZ/姿态 |
| 数据包3 | `0x0013` | 105 字节 | 数据包1 全集+时间戳+PPS 锁定状态与模式+预留 |
| 数据包4 | `0x0022` | 38 字节 | 时间戳/加计XYZ/陀螺XYZ |

- **CRC16 校验**：初值 `0x3692`、多项式 `0x8408`（反向），计算范围=帧头至数据域末字节，**只统计校验通过的帧**
- **帧级统计**（与 CAN 分支字段对齐）：每个报文 ID 独立统计 帧数 / 平均Hz / 瞬时Hz（1 秒窗口）/ 帧间隔（当前ms / 平均 / 最小 / 最大）
- **最新帧解析**：实时表格下方按协议（小端 intel）解析各包最新一帧的物理量
- **设备时间戳差值Δt统计**（数据包2/3/4，同 CAN 分支 0x091）：相邻帧设备 us 时间戳之差的 最新/平均/最小/最大 统计，用于排查设备侧丢帧/乱序/时间戳重置；全样本无过滤，异常差值不丢弃、直接体现为极值
- 帧同步状态机：逐字节同步，坏 CRC 帧、非法长度帧自动剔除并可恢复同步，帧间夹垃圾字节不受影响
- 多线程设计：串口接收线程 + 协议解析/统计线程（字节流 SPSC 环形队列衔接）+ 主线程周期打印
- 优雅退出：Ctrl+C 或限时到打印最终汇总（接收字节数/CRC 通过帧数/队列丢弃字节/各包统计）

## AT指令验证说明 (功能2)

依据《用户协议》第2章 AT 指令表逐条验证，判定规则：

| 组别 | 内容 | 判定 | 副作用处理 |
|---|---|---|---|
| 安全组 | 17 条只读查询（含 `CANBAUD?`/`FLASHCFG`/`ACCSCALECFG?`/`GYROSCALECFG?`）+ 数据流开关 + YAW归零 | 查询类按文档应答格式逐项匹配（如 `AppVersion:`/`UARTBaudRate:` + `OK`）；动作类收到 `OK` 即过 | SET 开关成对执行后恢复原态；YAW 归零为一次性动作 |
| 风险组 | PPS 开关与模式、MSGID=13/22 推送开关、GRAPHRQ/ORIGRQ 频率、DATALINK 链路开关、零偏校准、量程配置（ACCSCALECFG/GYROSCALECFG）、系统时间设置、RST 复位 | 同上 | **成对设计：先验证设置，紧接下发还原指令**（如 PPS=ON→PPS=OFF，DATALINK=UART,0→UART,1）；`DATATIME=` 先查原时间、验证后自动还原原时间（掉电不保存）；**量程配置先查原值、设避让档验证后立即写回原值**（HEX 版同指令为 FLASH 保存，AT 版最终状态不变）；`RST` 复位重启固定放用例表末尾 |
| 暂不内置 | BAUD/COORDINATE/PUSHFRQ/CANBAUD= 等掉电保存且影响链路或数据语义的项 | — | 改波特率会使本工具失联、改坐标系影响数据判读、改推送频率改变数据流语义，避免在自动流程中执行；如需验证建议手动单项进行 |

超时 800ms 无 `OK` 判 FAIL；数据流推送报文与 AT 应答共存于同一串口，且可能**字节级交织**（推送帧内可见字节打断关键字文本、噪声假 `OK` 提前截断缓冲）。接收路径先按帧结构整帧剔除 `AA 55` 推送帧，再要求"全部期望关键字 + `OK\r\n`"双条件齐备才截断应答；假 `OK`（其前无关键字）自动跳过继续等真应答，原始应答片段原样打印便于人工复核。

## HEX协议验证说明 (功能3)

依据《用户协议》第3.2章串口交互协议验证，覆盖 3.2.2 报文 ID 表全部 19 个交互 ID 中可执行的 18 个（0x0005 蓝牙名称文档明确不支持查询且写入掉电保存，有意排除）。帧格式 `AA 55 | CMD(ID高字节) | ID | Op | Len(2,小端,整帧长) | DATA | CRC16(2,小端)`，应答帧无 Op 字段；CRC16 初值 `0x3692`、多项式 `0x8408`（反向），范围=帧头至数据域末，与协议层 BspUartCrc16 同算法。

| 组别 | 内容 | 判定 | 副作用处理 |
|---|---|---|---|
| 安全组 | 13 个 ID 的查询（0x0003版本/0x0004频率/0x0006算法模式/0x0007推送状态/0x0012PPS/0x0015坐标系/0x0016串口波特率/0x0017CAN波特率/0x0018SN/0x0022加速度量程/0x0022角速度量程/0x0101A值/0x0103电量）+ 0x0021 YAW 归零（写 RAM 掉电不保存） | 应答帧 CRC 校验通过后按文档应答格式校验：数据域长度、值域白名单（频率档 0x01~0x09、坐标系 24 值表、波特率 7 值表、CAN 波特率 3 值表、SN 16 字节可打印、量程档位表 2/4/8/16g 与 250/500/1000/2000°/s）并提取关键值 | 查询结果同步缓存（频率档/算法模式/推送状态/PPS 开关与模式/坐标系），供风险组动态构造设置值与还原帧；**0x0022 与数据包4推送同 ID，量程查询按期望应答帧长 18 过滤推送帧混叠**；**0x0022 文档仅给设置帧格式，查询帧按候选格式自动探测（类型+预留8(CAN 0x115查询映射)/类型1/设置帧同构），命中格式在结果中标注** |
| 风险组 | 写 RAM（Op=0x01）：0x0004 频率、0x0006 算法模式、0x0007 推送开关、0x0011 报文推送开关（0x0022）、0x0012 PPS 开关、0x0015 坐标系、0x0008 磁力计校准、0x0020 零偏校准、0x0019 时间同步 | 应答 DATA[0]==0x00 即过 | **动态成对还原：设置值避让原值（如频率原档 10Hz 则设 20Hz），验证通过后立即用查询缓存构造还原帧下发（不计分）**；0x0019 时间同步写入主机当前时间（掉电不保存）；0x0014 复位重启固定放用例表末尾 |
| 有意排除 | 蓝牙名称 0x0005 写入（直接写蓝牙且掉电保存，无法还原；文档明确不支持查询）；0x0016/0x0017 写入（仅支持配置到 FLASH 且重启生效会断链）；**0x0022 量程写入（3.2.3.17 仅支持 FLASH 档，掉电保存；查询档已覆盖）**；各 ID 的 FLASH 档（Op=0x02，掉电保存）；0x0019 的"设原时间还原"（无查询报文，改为同步主机时间覆盖） | — | 如需验证建议手动单项进行 |

接收与数据流混流容错：滑窗搜索帧头 + CMD/ID 匹配 + CRC 校验，推送报文（如 0x0001）与坏帧自动剔除；每次事务前 `tcflush` 清残留。模式 0 仅安全组（默认），模式 1 加风险组；查询缓存无效时风险项自动 SKIP（避免无法还原）。

## 实时输出说明

终端下每秒原地刷新（管道输出则 5 秒全量打印）：

| 字段 | 单位 | 说明 |
|---|---|---|
| `帧数` | 帧 | 该报文累计收到的 CRC 通过帧数 |
| `平均Hz` | Hz | (帧数−1) ÷ (末帧时刻−首帧时刻)，全程平均 |
| `瞬时Hz` | Hz | 最近 1 秒窗口内帧数 ÷ 窗口时长 |
| `当前ms` | ms | 当前帧 − 上一帧的接收间隔 |
| `平均ms` | ms | 全部帧间隔的算术平均（理想值=推送周期） |
| `最小/最大ms` | ms | 帧间隔极值；明显偏离平均 → 存在断流或突发 |

解析区逐包显示最新物理量：加计（m/s²，静止时模长≈9.8）、陀螺（°/s）、温度（℃）、姿态（°）、四元数（模长应≈1）、磁场、设备时间戳（us）等。

Δt 统计每包一行 `0x10时间戳差值Δt: 最新 xx ms, 平均 xx ms, 最小 xx ms, 最大 xx ms, 样本 n`（数据包 2/3/4 各一行，无数据显示"等待第二个0xXX包..."，格式与统计语义均对齐 CAN 分支 0x091：全样本无过滤）：理想值=推送周期；全样本无过滤下极值即异常证据——最小 1ms 级毛刺/最大百万毫秒级跳变 → 设备侧时间戳回退或重置丢帧；平均接近推送周期仅极值毛刺 → 偶发抖动。

## 判读参考

- 50Hz 推送 → 平均间隔应 ≈ 20.0ms；1000Hz → ≈ 1.0ms
- `平均Hz` 与设置推送频率一致、`最大ms` 无大跳 → 流稳定无断流
- 队列丢弃字节 > 0 → 解析线程消费不及（正常情况应为 0）
- CRC 通过帧数 ≈ 接收字节数 ÷ 平均帧长 → 链路无误码

## 排障

- **统计/解析停滞、CRC 失败帧暴涨**：先查是否有别的进程占用同一串口（`lsof /dev/ttyUSB0`；曾因 30 分钟长跑的旧 uart_stat 实例未退出，新实例只收到残帧：11s 仅 2 帧通过、411 帧CRC失败）。两实例同时读会让字节流被瓜分，任何单实例都无法组出完整帧。
- **"最新帧解析"数值不动**：正常情况下每秒都在变（时间戳走秒/物理量微抖）；若完全冻结，优先怀疑串口被抢占而非协议解析（本工具解析为每帧无条件更新）。

## 已知限制

- 设备未授时时数据包 1/3 的日期时间为 1970 纪元起算（设备内部 uptime），属设备侧行为
- 数据包 4（0x0022）默认未开启推送（需 `AT+MSGID=22,1` 或 0x0011 指令开启），程序侧已支持解析
- 程序为纯被动接收，不主动下发推送开启指令（如需请参考 CAN 分支的按需下发思路扩展 0x0011 指令）
