# `IMU Linux` 双传输验证程序 (imu_test: UART串口 + SocketCAN)

[TOC]

## 概述

	本项目是基于志翔`IMU`的 Linux **测试验证程序**（单可执行 `imu_test`，双传输层统一入口），由 `feature/LinuxUartTestVerifDemo`（串口）与 `feature/LinuxCanTestVerifDemo`（CAN）两分支合并而成（V2.0.0）。

	**传输层判别**：第 1 参数设备名以 `can` 开头 → SocketCAN；其余 → UART 串口。两传输层各自独立的三层架构（驱动/队列/协议），统一入口按设备名分发：

- **UART 串口**（`./imu_test [串口] [波特率] [功能] [参数]`）：
	- **功能1 数据流统计**：接收志翔私有协议推送报文，实现数据包1/2/3/4 的帧级统计与解析，验证帧率是否达标、间隔是否均匀、有无断流、物理量解析正确性。
	- **功能2 AT指令验证**：依据《用户协议》第2章逐条下发 AT 指令并按文档应答格式判定，验证完成后自动还原配置。
	- **功能3 HEX协议验证**：依据《用户协议》第3.2章串口交互协议，对全部报文 ID 逐一下发查询/写入帧并按应答格式判定（Len/CRC/值域），写 RAM 项验证后依据查询缓存自动还原。
- **SocketCAN**（`./imu_test [接口] [功能] [参数]`）：
	- **功能1 数据流统计**：接收 0x091~0x098 数据报文做帧级统计与解析（帧率/间隔/Δt），并按需下发 0x103 自动恢复断流。
	- **功能2 CAN指令验证**：依据协议文档 3.3.3 章逐条实测 CAN 交互指令（安全/风险/异常组 + 压力模式），验证后自动还原。

## 功能特性

**公共统计能力**（两传输层字段与语义对齐）：

- **帧级统计**：每个报文 ID 独立统计 帧数 / 平均Hz / 瞬时Hz（1 秒窗口）/ 帧间隔（当前ms / 平均 / 最小 / 最大）
- **最新帧解析**：实时表格下方按协议（小端 intel）解析各 ID/包最新一帧的物理量
- **设备时间戳差值Δt统计**：相邻帧设备 us 时间戳之差的 最新/平均/最小/最大 统计（UART=数据包2/3/4，CAN=0x091）；全样本无过滤，异常差值不丢弃、直接体现为极值
- 多线程设计：接收线程 + 协议解析/统计线程（队列衔接）+ 主线程周期打印
- 优雅退出：Ctrl+C 或限时到打印最终汇总
- 终端每秒原地刷新统计（管道/重定向输出则 5 秒全量打印）

**UART 串口专属**：

- 串口驱动：`termios` 原始模式，默认 `921600 8N1`（协议默认），支持 9600~921600 常用波特率，使能 `ASYNC_LOW_LATENCY` 降低 USB 串口延迟
- 协议支持：志翔私有协议帧 `AA 55 | CMD | ID | LEN(2, 小端) | DATA | CRC16(2, 小端)`，LEN 为整帧长度
- **数据包统计与解析**（CMD=0x00 通用报文）：

| 数据包 | 报文ID  | 数据域长度 | 内容 |
|---|---|---|---|
| 数据包1 | `0x0001` | 87 字节 | 频率/日期时间/加计XYZ+模长/陀螺XYZ+模长/温度/姿态/四元数/磁场 |
| 数据包2 | `0x0010` | 44 字节 | 时间戳/加计XYZ/陀螺XYZ/姿态 |
| 数据包3 | `0x0013` | 105 字节 | 数据包1 全集+时间戳+PPS 锁定状态与模式+预留 |
| 数据包4 | `0x0022` | 38 字节 | 时间戳/加计XYZ/陀螺XYZ |

- **CRC16 校验**：初值 `0x3692`、多项式 `0x8408`（反向），计算范围=帧头至数据域末字节，**只统计校验通过的帧**
- 帧同步状态机：逐字节同步，坏 CRC 帧、非法长度帧自动剔除并可恢复同步，帧间夹垃圾字节不受影响
- 字节流 SPSC 环形队列（4KB）衔接收发线程，退出汇总含接收字节数/CRC 通过帧数/队列丢弃字节

**SocketCAN 专属**：

- `SocketCAN`驱动：内核级接收过滤器，只接收`0x091`~`0x098`数据报文与 0x100~0x115 交互指令（只匹配标准帧）
- 协议支持：`0x091`~`0x098`共 8 个数据报文解析（小端 intel），8 帧收齐即一组完整 IMU 数据
- 自动开启推送（按需）：启动后若 2 秒宽限期内收不到首帧、或运行中数据流中断超过 3 秒，才下发`0x103`指令开启推送，之后每 3 秒重试直到数据恢复——数据正常时**一次都不发**
- 帧级环形队列（256 帧）衔接收发线程，退出汇总含队列丢帧计数

## 构建与运行

```bash
# 一键编译并运行（判别传输层: 第1参数can开头=CAN, 其余=UART, 不带参数=交互选择; ./run.sh -h 详细帮助）
./run.sh

# UART: 指定串口/波特率/限时10秒
./run.sh /dev/ttyUSB0 921600 10

# CAN: 指定接口, 数据流统计10秒自动汇总退出
./run.sh can0 10

# 手动编译(单程序, 双传输全部源文件)
gcc -O2 -Wall -o imu_test main.c \
    uart/drv_serial.c uart/bsp_uart_queue.c uart/bsp_uart_protocol.c \
    uart/bsp_at_test.c uart/bsp_hex_test.c \
    can/drv_socketcan.c can/bsp_can_queue.c can/bsp_can_protocol.c \
    can/bsp_can_test.c -lpthread
```

统一用法：`./imu_test [设备名] [功能] [功能参数]`（设备名 can 开头=SocketCAN，否则=UART 串口）

| 传输层 | 功能 | 参数 | 功能参数 | 示例 |
|---|---|---|---|---|
| UART | 1=数据流统计（默认） | `[串口] [波特率] [秒数]` | 第3参数非 2/3 时视为持续秒数，0=直到 Ctrl-C | `./imu_test /dev/ttyUSB0 921600 10` |
| UART | 2=AT指令验证 | `[串口] [波特率] 2` | 模式：0=仅安全组（默认），1=安全组+风险组（验证后自动还原） | `./imu_test /dev/ttyUSB0 921600 2 1` |
| UART | 3=HEX协议验证 | `[串口] [波特率] 3` | 模式：0=仅安全组（默认），1=安全组+风险组+异常组，2=压力/暴力测试 | `./imu_test /dev/ttyUSB0 921600 3 0` |
| CAN | 1=数据流统计（默认） | `[接口] [秒数]` | 秒数 0=直到 Ctrl-C | `./imu_test can0 10` |
| CAN | 2=CAN指令验证 | `[接口] 2` | 模式：0=仅安全组（默认），1=安全组+风险组+异常组，2=压力/暴力测试 | `./imu_test can0 2 1` |

CAN 环境要求：Linux + GCC + CAN 接口（如 USB转CAN适配器，驱动已加载，如 `sudo modprobe gs_usb`）。运行前配置接口（波特率需与 IMU 一致，协议默认 1000K）：

```bash
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
```

IMU 的 CAN 推送链路无需提前配置：程序会按需自动下发 `0x103` 开启推送（数据正常时一次都不发）。

## AT指令验证说明 (UART 功能2)

依据《用户协议》第2章 AT 指令表逐条验证，判定规则：

| 组别 | 内容 | 判定 | 副作用处理 |
|---|---|---|---|
| 安全组 | 17 条只读查询（含 `CANBAUD?`/`FLASHCFG`/`ACCSCALECFG?`/`GYROSCALECFG?`）+ 数据流开关 + YAW归零 | 查询类按文档应答格式逐项匹配（如 `AppVersion:`/`UARTBaudRate:` + `OK`）；动作类收到 `OK` 即过 | SET 开关成对执行后恢复原态；YAW 归零为一次性动作 |
| 风险组 | PPS 开关与模式、MSGID=13/22 推送开关、GRAPHRQ/ORIGRQ 频率、DATALINK 链路开关、零偏校准、量程配置（ACCSCALECFG/GYROSCALECFG）、系统时间设置、RST 复位 | 同上 | **成对设计：先验证设置，紧接下发还原指令**（如 PPS=ON→PPS=OFF，DATALINK=UART,0→UART,1）；`DATATIME=` 先查原时间、验证后自动还原原时间（掉电不保存）；**量程配置先查原值、设避让档验证后立即写回原值**（HEX 版同指令为 FLASH 保存，AT 版最终状态不变）；`RST` 复位重启固定放用例表末尾 |
| 暂不内置 | BAUD/COORDINATE/PUSHFRQ/CANBAUD= 等掉电保存且影响链路或数据语义的项 | — | 改波特率会使本工具失联、改坐标系影响数据判读、改推送频率改变数据流语义，避免在自动流程中执行；如需验证建议手动单项进行 |

超时 800ms 无 `OK` 判 FAIL；数据流推送报文与 AT 应答共存于同一串口，且可能**字节级交织**（推送帧内可见字节打断关键字文本、噪声假 `OK` 提前截断缓冲）。接收路径先按帧结构整帧剔除 `AA 55` 推送帧，再要求"全部期望关键字 + `OK\r\n`"双条件齐备才截断应答；假 `OK`（其前无关键字）自动跳过继续等真应答，原始应答片段原样打印便于人工复核。

## HEX协议验证说明 (UART 功能3)

依据《用户协议》第3.2章串口交互协议验证，覆盖 3.2.2 报文 ID 表全部 19 个交互 ID 中可执行的 18 个（0x0005 蓝牙名称文档明确不支持查询且写入掉电保存，有意排除）。帧格式 `AA 55 | CMD(ID高字节) | ID | Op | Len(2,小端,整帧长) | DATA | CRC16(2,小端)`，应答帧无 Op 字段；CRC16 初值 `0x3692`、多项式 `0x8408`（反向），范围=帧头至数据域末，与协议层 BspUartCrc16 同算法。

| 组别 | 内容 | 判定 | 副作用处理 |
|---|---|---|---|
| 安全组 | 13 个 ID 的查询（0x0003版本/0x0004频率/0x0006算法模式/0x0007推送状态/0x0012PPS/0x0015坐标系/0x0016串口波特率/0x0017CAN波特率/0x0018SN/0x0022加速度量程/0x0022角速度量程/0x0101A值/0x0103电量）+ 0x0021 YAW 归零（写 RAM 掉电不保存） | 应答帧 CRC 校验通过后按文档应答格式校验：数据域长度、值域白名单（频率档 0x01~0x09、坐标系 24 值表、波特率 7 值表、CAN 波特率 3 值表、SN 16 字节可打印、量程档位表 2/4/8/16g 与 250/500/1000/2000°/s）并提取关键值 | 查询结果同步缓存（频率档/算法模式/推送状态/PPS 开关与模式/坐标系），供风险组动态构造设置值与还原帧；**0x0022 与数据包4推送同 ID，量程查询按期望应答帧长 18 过滤推送帧混叠**；**0x0022 文档仅给设置帧格式，查询帧按候选格式自动探测（类型+预留8(CAN 0x115查询映射)/类型1/设置帧同构），命中格式在结果中标注** |
| 风险组 | 写 RAM（Op=0x01）：0x0004 频率、0x0006 算法模式、0x0007 推送开关、0x0011 报文推送开关（0x0022）、0x0012 PPS 开关、0x0015 坐标系、0x0008 磁力计校准、0x0020 零偏校准、0x0019 时间同步 | 应答 DATA[0]==0x00 即过 | **动态成对还原：设置值避让原值（如频率原档 10Hz 则设 20Hz），验证通过后立即用查询缓存构造还原帧下发（不计分）**；0x0019 时间同步写入主机当前时间（掉电不保存）；0x0014 复位重启固定放用例表末尾 |
| 异常组 | 9 条（模式1与风险组同开，总 32 条）：① 静默无应答类——CRC 错误帧/非法操作符 0x01/未知报文 ID 0x0023/Len 超限/0x0008 磁力计校准（**固件差异发现**：文档有 0x0008 但固件分发表无此 ID，真机实测静默，按"预期无应答"验证，超时即 PASS）；② 无效应答类——频率 0x0004 非法操作符 0x03（固件末尾无条件应答）；③ 非法值写入→行为查询（ABN_WQ）——频率非法档 0x0A 回落档 5（50Hz）/坐标系非法值直写无校验/PPS 非法模式归零 | 预期以固件实际行为为准 | 写入应答成功后查询确认固件行为，还原由外层统一执行 |
| 有意排除 | 蓝牙名称 0x0005 写入（直接写蓝牙且掉电保存，无法还原；文档明确不支持查询）；0x0016/0x0017 写入（仅支持配置到 FLASH 且重启生效会断链）；**0x0022 量程写入（3.2.3.17 仅支持 FLASH 档，掉电保存；查询档已覆盖）**；各 ID 的 FLASH 档（Op=0x02，掉电保存）；0x0019 的"设原时间还原"（无查询报文，改为同步主机时间覆盖） | — | 如需验证建议手动单项进行 |

接收与数据流混流容错：滑窗搜索帧头 + CMD/ID 匹配 + CRC 校验，推送报文（如 0x0001）与坏帧自动剔除；每次事务前 `tcflush` 清残留。模式 0 仅安全组（默认），模式 1 加风险组+异常组；查询缓存无效时风险项自动 SKIP（避免无法还原）。模式 2 为压力/暴力测试（见版本历史 V1.7.10）。

| ------ | ------------ | ------------ | ---- |

| 0x092  | Roll | Pitch | ° |
| 0x093  | Yaw | IMU温度 | ° / ℃ |
| 0x094  | 四元数q1 | 四元数q2 |  |

## CAN指令验证说明 (CAN 功能2)

依据协议文档 3.3.3 章对每条 CAN 交互指令做实测验证（帧格式逐 ID 对照固件工程 `bsp_parse.c` 核实），架构与串口 HEX 验证器一致：安全组/风险组、查询校验键→函数分发表、缓存驱动自动还原、安静模式逐条输出+汇总表。

- **帧格式**：标准帧，`can_id`=指令ID(0x100~0x115)，DLC=8，`data[0]`=操作符(0x00查询/0x01写RAM/0x02写FLASH)，`data[1..7]`=参数；应答帧同 ID，写操作应答 8 字节全 0
- **数据流容错**：内核过滤器只收 0x100~0x115，0x091~0x098 推送帧不进用户态
- **用例覆盖**（32 条）：安全组 15 查询 + YAW 归零；风险组 7 条 RAM 写入（频率避让档/坐标系切异值/数据流开关取反/0x22 推送取反/PPS 开关取反/精简流取反/零偏校准开启）验证后自动还原原值；**异常组 8 条**（与风险组同开关，预期以固件实际行为为准）：无效操作符静默（0x100/0x105/0x115 非法类型/未知 ID 0x116 均无应答）、无效操作符无效应答（0x101 回全 0）、非法频率档回落验证（固件回落 50Hz 档 5）、非法坐标系/PPS 模式直写行为确认+还原；复位重置表末
- **异常组发现**：固件 0x102 坐标系/0x109 PPS 模式**无值域校验直写**非法值（工具记录行为并立即还原；固件将来加校验时这两条会 FAIL 以提示行为变化）
- **压力/暴力模式**（功能2第3参数=2，对齐 HEX 验证器模式2）：① 无效请求静默（非法操作符 0xFF+未知 ID 0x116，预期无应答）；② 高频连发 200 帧不等应答（统计固件实际接收数）；③ 未知 ID 轰炸 200 轮（随机 0x116~0x1FF 后合法版本查询验证恢复，恢复率≥90% 判 PASS）；④ fuzz 随机请求轰炸 500 帧（固定种子可复现，只用版本/SN/未知 ID 无副作用集+随机操作符与参数）；每项结束版本查询探活（3 重试），失败自动 0x110 复位兜底重启再探活。CAN 适配：无字节流截断概念，以未知 ID 轰炸替代 HEX 截断恢复项
- **固件对照结论**（以固件为准的差异）：0x104 固件支持查询（文档标不支持，应答 `[1]`=子ID回显`[2]`=开关）；0x115 量程配置文档缺失但固件已实现（查询 `[1]`=类型 1 加计/2 角速度，应答量程小端 2 字节）；SN 低/高 8 字节固件按倒序填充；0x110 复位仅 RAM 档应答
- **有意排除**：CAN/串口波特率写入（FLASH+重启生效，改 CAN 波特率直接断链）、UART 开关写入（FLASH+重启生效）、0x115 量程写入（仅 FLASH 档掉电保存）、各 ID 的 FLASH 档（0x02）
- **风险组还原**：依赖安全组查询缓存构造还原帧（频率/坐标系/数据流/0x22/PPS/精简流回原值，零偏=清除校准值），还原动作不计分；缓存无效时用例自动 SKIP 保护

## 实时输出说明

终端下每秒原地刷新（管道输出则 5 秒全量打印），统计表格字段两传输层一致：

| 字段 | 单位 | 说明 |
|---|---|---|
| `ID`/`报文` | — | UART=数据包1~4 报文 ID（0x0001/0x0010/0x0013/0x0022）；CAN=0x091~0x098 |
| `帧数` | 帧 | 该报文累计收到的校验通过帧数（UART=CRC16 通过；CAN=完整帧） |
| `平均Hz` | Hz | (帧数−1) ÷ (末帧时刻−首帧时刻)，全程平均 |
| `瞬时Hz` | Hz | 最近 1 秒窗口内帧数 ÷ 窗口时长，反映当前实际节奏（与平均Hz对比可发现断流/变速） |
| `当前ms` | ms | 当前帧 − 上一帧的接收间隔 |
| `平均ms` | ms | 全部帧间隔的算术平均（理想值=推送周期） |
| `最小/最大ms` | ms | 帧间隔极值；明显偏离平均 → 存在断流或突发 |

解析区逐 ID/包显示最新物理量：加计（m/s²，静止时模长≈9.8）、陀螺（°/s）、温度（℃）、姿态（°）、四元数（模长应≈1）、磁场（UART）、设备时间戳（us）等。CAN 解析区另含 `原始数据(B0~B7)` 列（最新一帧 8 字节原始数据）。

### Δt 统计（设备时间戳差值）

UART 数据包2/3/4 与 CAN 0x091 载荷均含设备内部时间戳（uint64，us）。程序对**相邻两帧的时间戳做差**：`Δt = 本包时间戳 − 上一包时间戳`（单位 ms），与主机接收侧的`当前ms`相互独立：

- 两者接近 → 设备按真实节奏推流，时间戳可信；
- 接收间隔正常但 Δt 为 0 或跳变 → 设备时间戳本身异常（冻结/回绕/复位）。

每包一行 `0xXX时间戳差值Δt: 最新 xx ms, 平均 xx ms, 最小 xx ms, 最大 xx ms, 样本 n`（无数据显示"等待第二个0xXX包..."）；理想值=推送周期（1000Hz → 1.000ms）。全样本无过滤下极值即异常证据——最小 1ms 级毛刺/最大百万毫秒级跳变 → 设备侧时间戳回退或重置丢帧；平均接近推送周期仅极值毛刺 → 偶发抖动。

## 判读参考

- 50Hz 推送 → 平均间隔应 ≈ 20.0ms；1000Hz → ≈ 1.0ms
- `平均Hz` 与设置推送频率一致、`最大ms` 无大跳 → 流稳定无断流
- 理想周期帧：`当前ms` 紧贴平均值小幅波动，`最小ms`/`最大ms` 对称包裹平均值
- `最大ms` 明显大于平均值 → 存在掉帧或发送端卡顿
- `瞬时Hz` 长期低于 `平均Hz` → 数据流变慢或已断流
- 解析值为 0 且长期不变 → 发送端未更新该字段（结合原始数据字节判断）
- UART：队列丢弃字节 > 0 → 解析线程消费不及（正常情况应为 0）；CRC 通过帧数 ≈ 接收字节数 ÷ 平均帧长 → 链路无误码
- CAN：退出汇总的队列丢帧数 > 0 → 接收负载过高（正常情况应为 0）

## 排障与常见问题

- **UART 统计/解析停滞、CRC 失败帧暴涨**：先查是否有别的进程占用同一串口（`lsof /dev/ttyUSB0`；曾因 30 分钟长跑的旧实例未退出，新实例只收到残帧）。两实例同时读会让字节流被瓜分，任何单实例都无法组出完整帧。
- **UART "最新帧解析"数值不动**：正常情况下每秒都在变（时间戳走秒/物理量微抖）；若完全冻结，优先怀疑串口被抢占而非协议解析（本工具解析为每帧无条件更新）。
- **CAN 打开接口失败** `ioctl SIOCGIFINDEX fail (接口不存在?)`：确认接口名正确（`ip link show type can`）；确认接口已UP（`ip link show can0` 中应有 `state UP`）；USB转CAN适配器需先加载驱动，如 `sudo modprobe gs_usb`；权限不足时使用 `sudo ./imu_test can0` 或将用户加入 netdev 组。

## 已知限制

- 设备未授时时 UART 数据包 1/3 的日期时间为 1970 纪元起算（设备内部 uptime），属设备侧行为
- UART 数据包 4（0x0022）默认未开启推送（需 `AT+MSGID=22,1` 或 0x0011 指令开启），程序侧已支持解析；UART 功能1 为纯被动接收，不主动下发推送开启指令（CAN 侧已有按需下发 0x103 思路可参考）
- CAN 压力/暴力模式在本机无 CAN 接口环境下仅过逻辑单测，真机验证需硬件接入后进行
