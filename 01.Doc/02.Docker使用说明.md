# IMUDemo ROS2 Docker 使用说明

> 适用环境：宿主机 Ubuntu 22.04 + Docker，ROS 2 Humble 容器
> 本文档面向 Docker 初学者，覆盖：镜像拉取 → 容器创建 → 目录挂载 → 编译 → 运行 → 日常使用

---

## 一、Docker 是什么？（小白版）

可以把 Docker 理解成**一台台轻量的"虚拟机"**，但比虚拟机更轻、启动更快。

| 概念 | 通俗理解 | 类比 |
|------|---------|------|
| **镜像 (Image)** | 一个只读的"系统安装光盘"，里面装好了 Ubuntu + ROS | Ghost 系统盘 / 安装 U 盘 |
| **容器 (Container)** | 用"光盘"启动起来的一台正在（或曾经）运行的机器 | 装好系统的那台电脑 |
| **挂载 (Volume / -v)** | 把宿主机的一个文件夹"映射"进容器里 | 相当于给容器插了一个共享网盘 |
| **设备挂载 (--device)** | 把宿主机的一个硬件（如串口）交给容器使用 | 相当于把 U 盘/串口线插到容器这台"电脑"上 |

### 三个关键认知

1. **镜像 → 容器**：一个镜像可以创建任意多个容器。镜像不变，容器是各自独立的。
2. **容器删了，里面的东西就没了**：在容器里 `apt install` 装的软件、写在容器硬盘上的文件，都会随 `docker rm` 一起消失。**只有通过 `-v` 挂载进来的目录是安全的**——它其实就是宿主机上的目录。
3. **容器停止 ≠ 删除**：`exit` 退出后容器还在（只是关机了），下次可以再启动，里面装的东西都还在。

## 二、常用命令速查表

```bash
sudo docker pull 镜像名            # 下载镜像（相当于下载系统盘）
sudo docker images                # 查看本机已有的镜像
sudo docker run -it 镜像名 bash    # 用镜像创建并进入一个新容器
sudo docker ps                    # 查看正在运行的容器
sudo docker ps -a                 # 查看所有容器（含已停止的）
sudo docker start -ai 容器名       # 启动已停止的容器并进入（日常最常用）
sudo docker exec -it 容器名 bash   # 另开一个终端进入正在运行的容器
sudo docker rm 容器名              # 删除容器（容器里装的东西随之丢失）
sudo docker rmi 镜像名             # 删除镜像
```

> **为什么都要 sudo？** 当前用户 `yym` 不在 `docker` 组里。想免 sudo 可执行
> `sudo usermod -aG docker yym`，注销重新登录后生效。

## 三、拉取 ROS 2 镜像

```bash
sudo docker pull ros:humble
```

- `ros` 是官方 ROS 镜像名，`humble` 是标签（tag），对应 **ROS 2 Humble**，与宿主机 Ubuntu 22.04 配套。
- 验证是否拉取成功：

```bash
sudo docker images
# 应能看到一行： ros    humble   xxxx   xxxx
```

> ⚠️ 注意：本机原有的 `ros:noetic-ros-base` 是 **ROS 1**，与本工程（ROS 2）不兼容，不要用。

### ROS 版本对照（避免以后踩坑）

| Ubuntu 宿主机 | ROS 1 | ROS 2 |
|---------------|-------|-------|
| 20.04 | Noetic | Foxy / Galactic |
| **22.04（本机）** | ❌ 无 | **Humble ✅** |
| 24.04 | ❌ 无 | Jazzy |

## 四、创建容器（含串口与工作目录挂载）

### 一条命令

```bash
sudo docker run -it --name imu_ros2 \
  --device /dev/ttyUSB0 \
  --device /dev/ttyUSB1 \
  -v /media/yym/3326F555A9DAFEB8/IMUDemo/00.Code:/workspace \
  ros:humble \
  bash
```

### 参数逐个解释

| 参数 | 含义 |
|------|------|
| `-it` | 交互式运行（interactive + tty），进去后能敲命令 |
| `--name imu_ros2` | 给容器起名字，以后用这个名字启动/进入它 |
| `--device /dev/ttyUSB0` | 把宿主机的串口设备 0 交给容器（IMU 可能在这个口） |
| `--device /dev/ttyUSB1` | 同上，串口设备 1（两个都挂，省得猜哪个是 IMU） |
| `-v 宿主机路径:容器内路径` | 把宿主机的代码目录挂载为容器里的 `/workspace` |
| `ros:humble` | 用哪个镜像创建 |
| `bash` | 进容器后执行的程序（也就是给我们一个 shell） |

### 关于挂载的几点说明

- 挂载是**双向实时**的：在容器里改 `/workspace` 下的文件 = 改宿主机 `00.Code` 下的文件，反之亦然。
- 挂载目录里的代码**不会**随容器删除而丢失，它本来就在宿主机上。
- **串口设备必须在 `docker run` 时挂上**，运行中的容器事后补挂很麻烦。如果发现忘挂了，最简单的办法是：删掉容器重新 `docker run`（代码在宿主机上，删容器不心疼）。
- `IMU 串口编号可能会变`：拔插 USB 后 `ttyUSB0/1` 可能互换。若收不到数据，可把两个口都挂上（如上），再在配置里换着试。

## 五、容器内：安装编译工具（只需一次）

进入容器后默认是 `root` 用户，**不需要 sudo**。

ROS 官方镜像不带 colcon（编译工具），需要先安装：

```bash
apt update
apt install -y python3-colcon-common-extensions
```

> 只要容器不删（不执行 `docker rm imu_ros2`），装一次永久有效。

---

## 六、编译

```bash
cd /workspace
colcon build
```

- 编译产物生成在 `/workspace/install/` 目录（即宿主机的 `00.Code/install/`）。
- 编译报错想看详细过程：

```bash
colcon build --event-handlers console_direct+
```

- 改了代码、配置或消息定义后，**重新执行 `colcon build`** 才会生效。
- 清空重来：

```bash
rm -rf build install log
colcon build
```

## 七、加载环境并运行

```bash
source install/setup.bash
ros2 launch zhixiang_imu_ros2 imu_spec_msg.launch.py
```

- `source install/setup.bash`：把刚编译好的包注册进 ROS 环境。**每新开一个终端都要重新 source 一次**，否则 `ros2 launch` 会报 `package not found`。
- 这条 launch 会同时启动两个节点：
  - `talker`：打开串口、解析 IMU 数据、发布 `/imu_data1` `/imu_data2` `/imu_data3`
  - `listener`：订阅这三个话题并打印
- 停止运行：终端里按 `Ctrl + C`。

### 验证数据（另开一个终端）

宿主机上再开一个终端：

```bash
sudo docker exec -it imu_ros2 bash     # 进入正在运行的容器（不干扰上面的 launch）
cd /workspace && source install/setup.bash
ros2 topic hz /imu_data1               # 查看话题发布频率
ros2 topic echo /imu_data1             # 查看话题数据内容
```

## 八、日常使用流程（背下来这三条就行）

**每天开始干活：**

```bash
sudo docker start -ai imu_ros2         # 1. 启动并进入容器
cd /workspace && source install/setup.bash   # 2. 进工作目录、加载环境
ros2 launch zhixiang_imu_ros2 imu_spec_msg.launch.py   # 3. 运行
```

**下班/干完活：** 直接 `exit` 退出（容器自动停止，不会丢东西）。

**改了代码后：** 重新 `colcon build` → `source install/setup.bash` → 再 launch。

## 九、常见问题（FAQ）

| 现象 | 原因与解决 |
|------|-----------|
| `ros2: command not found` | 进错容器了（ROS 1 Noetic 容器里没有 ros2）。用 `sudo docker start -ai imu_ros2` 进 Humble 容器 |
| `package 'zhixiang_imu_ros2' not found` | 忘了 `source install/setup.bash` |
| `colcon: command not found` | 容器是新建的，没装 colcon。回到第五节安装 |
| `Permission denied: /dev/ttyUSB0` | 容器启动时没挂 `--device`。删容器重建（第四节） |
| 串口打开成功但收不到数据 | ① IMU 在另一个串口上：改 `src/config/imu_config.yaml` 里的 `serial_port`（`/dev/ttyUSB0` ↔ `/dev/ttyUSB1`），重新 `colcon build`；② 波特率不匹配：确认与配置里 `baud_rate: 921600` 一致 |
| 改了配置/launch/msg 不生效 | 这类文件是 `colcon build` 时拷贝到 `install/` 的，改完源文件必须重新 build |
| `docker: Cannot connect to the Docker daemon` | Docker 服务没起来：`sudo systemctl start docker` |
| 想看容器里 apt 装过什么 | `sudo docker exec -it imu_ros2 bash` 后正常查看即可 |
